研究运行入口对每次实际模型调用分别保存结果、模型名称、服务商和用量；只有调用方明确复用相同的幂等键时才在发起调用前返回已保存结果。固定演示仍可复用相同结果。

由模型研究运行写入的角色意见标为 `llm` 并记录模型名称；手工 API 不能自行冒充模型来源。旧记录保留原样，不能仅凭旧记录中 `manual` 标签推断其实际来源。

「仓位风险情景」支持手工输入线性 USDT 合约方向、权益、入场价、止损成交价、更不利的跳空成交价、张数、每张标的数量、杠杆和假设双向手续费，比较两个假设成交情景。它不会读取账户或下单；不计算资金费、维持保证金档位、强平、其他持仓和部分成交，不应将名义价值除杠杆视为交易所实际保证金。止损不能保证按输入价成交，可能先触发强平。数据只保留在当前页面会话；仅在聊天页主动勾选并提交后才会把该情景传给配置的模型服务商。

- `perps.research` 是**额外自建离线压力研究账本，不是Freqtrade原生成交引擎、不是交易所模拟成交**。仅一个全局仓位；历史资金费率按同期开盘价作为标记价代理；单边滑点0.05%、吃单费率读真实公开元数据。先入场、再处理当小时内部止损，避免用未来止损释放的资金支持同小时开仓。
- 离线账本：单日亏损达到3%或总损失10%触发锁定停机并在观察到的收盘退出；停机后本次运行不自动重启、不补保证金。阈值不是最大亏损保证，止损/跳空可越过阈值。没有完整维持保证金档位、盘中标记价、强平费与ADL模型；出现保证金压力越界就标记结果不合格，负权益直接报错。
- `freqtrade/strategies/BitgetBaseline.py` 是**原生框架候选集成**：多空逐仓、单向仓位、上述风险预算、2ATR回调止损、模拟配置；初始化与启动均禁止live/密钥，回调出错拒单而非回落到默认大仓位。其2次止损后冷却24小时保护与原生撮合假设不同于额外账本，不能声称两个结果相同。初始备用止损是保证金收益率-10%，ATR回调在after_fill及后续循环收紧；尚未验证为交易所托管止损。
- 默认 `stoploss_on_exchange=false`：只在本地/回测模拟止损，断网并没有交易所托管保护。未来真实交易必须单独验证触发价类型、reduce-only、止损回报与断线恢复；当前不得切换实盘。

# 以下为旧版 BTC现货 / GLD / QQQ 文档（无杠杆基线，不适用于新合约）

# trading-lab（研究 + 信号回放原型）

本地研究工具，用来回测一个非常简单的**日线多头/现金趋势**，并回放「最新已完成 K 线」给出的下一时段意向单。

**不是实盘交易系统，不保证盈利，也不能把云电脑当成 7x24 托管。** 模拟资金 100,000 USD 只是示例，不代表任何真实持仓。大模型不参与信号和风控。

评估日期与页面时间一律按 **Asia/Shanghai** 标注。

## 标的（代理，不是指数本身）

| 代码 | 含义 | 日历 |
| --- | --- | --- |
| BTC-USD | Bitcoin 现货 | 按 UTC 自然日的 24/7 日线（以数据源实际给出的日期为准，**不补造缺失日**） |
| GLD | 黄金的可交易代理（ETF）。**不是** XAU 现货、GC 期货或国内黄金 TD | 纽约证券交易所时段，不用周末虚构交易 |
| QQQ | 纳斯达克100 的可交易代理（ETF）。**不是** 指数本身，也不带杠杆 | 同上 |

ETF 默认用 yfinance 的复权 OHLC（`auto_adjust=true`），以便拆分/分红后的开盘价与收盘价一致。若改用 `data/csv/` 自行导入，请自己保证复权口径一致。

## 策略与执行（锁定默认）

- 规则：若**已完成**收盘价高于 200 日均线，则在该标的**下一交易时段开盘**买入或保持多头；否则在下一开盘卖到现金。
- 不用当根收盘价成交，也不偷看未来 K 线。
- 未完成的当日 K 线会被丢弃，不参与信号。
- 费用与滑点（示例，不是建议）：BTC 各 0.10%，GLD/QQQ 各 0.05%，买卖双向都计。
- 风控示例（写在 `config/default.yaml`，不是账户建议）：单标的上限 40%，现金下限 20%，从净值高点回撤 20% 后停止**新开仓**（已有多头仍可按信号卖出）。只做多，不融资，不做空，总多头 ≤ 100%。现金不够就减买，绝不透支。
- 样本切分锁定：历史从 2018-01-01 起，训练段到 2023-12-31，测试段从 2024-01-01 起到最近已完成数据。200 日窗口与上述阈值在测试段不再调参。均线在全样本上滚动，但只用已经发生的收盘，这是因果的。
- 基准：测试段一次性等权买住。该基准接近满仓，和带现金下限的策略风险不同。

## 回测和「纸上」的区别

- **回测**：在历史已出现的下一根开盘上模拟成交。
- **最新信号回放（`paper`）**：根据最近已完成 K 线给出意向单。**不是**一直运行的模拟交易服务器。如果下一根开盘还没出现，**不会**用最近收盘价虚构成交，也不会假设无限成交。
- 任一标的行情被判定为过期时，**停止发出新信号**。

## 为什么组合引擎不是 vectorbt 直接跑的

已安装并核实 **vectorbt 1.2.1**（Apache 2.0 + Commons Clause，个人研究可用，但不能把该软件作为收费托管服务出售）。许可证原文见环境里的 `LICENSE.md` 或 [上游仓库](https://github.com/polakowo/vectorbt/blob/master/LICENSE.md)。

vectorbt 适合单资产、整齐日历的信号仿真。本原型要同时处理 BTC 的 24/7 日历与 ETF 的美股日历、现金下限和集中度上限，因此**组合记账以 `trading_lab.engine` 的显式日频循环为准**。这是刻意的透明选择，不是悄悄换掉 vectorbt。vectorbt 仍作为已安装依赖，供单资产对照（`trading_lab.vectorbt_check`）。

新核验记录还会比较模型方向与输入截止前 24 小时动量方向；只在两者和实际变动均非零时给出配对计数。研究区间是否覆盖实际收盘也只计次数，不当作已经校准的概率。旧版已写入结果没有这两项，不会回填或悄悄修改，因此这些指标的样本数可能少于总样本数；频繁采集产生的重叠窗口也不能视为相互独立。

研究请求的小时线与日线指标根据快照完成时间重新检查数据质量：未来收盘、缺口或超过现有数据质量规则允许的年龄时，对应指标显示不可用，多周期关系显示不完整。现行年龄上限分别为 2 小时和 2 天；这是数据检查阈值，不保证行情可用于交易。

公开资金费率附带本机 UTC 采集时间和来源；接口返回错误或标的不匹配时保留缺失。采集时间不是交易所的费率生效时间，当前费率快照也不能冒充历史实际结算或预测未来资金费。

聊天界面显示冻结的费率和采集时间；实际向配置的模型提问时，再按当前时间检查费率是否在 5 分钟内、来源和数值是否有效。不可用时传递缺失标记，并从 ticker 摘要移除未经同样检查的重复费率字段。此规则只适用于实时研究快照，不补齐历史资金费。

向配置的模型提问时也会使用冻结的日线原始数据重新检查日线时效与完整性，然后重新计算多周期背景；日线缺失或超出数据质量年龄阈值时，会向模型标记缺失，并将多周期对齐标为不完整。这个复核不获取新行情，也不把均线关系变成买卖信号。

研究包还给出最近 20 个已完成 UTC 日线的历史最高、最低，以及最后一根已完成小时线收盘价相对该区间的位置；日线与小时线时间不一致时显示不可用。UTC 零点收盘的小时包含在刚完成的日线区间内，会专门标记。该字段供聊天分析观察，不等同于研究候选使用小时高低触及的突破条件，也不是价格预测、下单许可或经过验证的交易信号。

聊天分析附带程序化证据门控，并在模型返回后再次检查快照和报价时效、K 线质量、研究包与本地存档的一致性、已运行预测的绑定和当前纸面风控配置。完整研究包缺失或其他必要检查失败时，模型提出的纸面计划审查会降级为需要更多证据；仍可查看研究意见与阻断原因。历史聊天快照过期后界面会提醒。门控通过也不代表策略有效、强平价格已验证或获得交易授权；模型角色可由同一模型担任，不构成独立模型审查。

模型返回后还会检查各角色是否提供已验证的观点、是否存在被标记的无依据观点或疑似指令文本。当前引用检查只能检查证据编号存在，**不能验证证据是否支持观点**，因此一般模型观点被标为未验证，会阻断纸面计划审查；这不影响查看观点。疑似指令检测采用简单关键词，可能误报，也不能保证发现全部注入。
